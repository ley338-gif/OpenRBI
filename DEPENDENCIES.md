# Dependencies

This document tracks the central third-party components OpenRBI relies on: what they do, why they were chosen, their license, and possible alternatives. Versions and licenses are verified against the actual pinned version in use, not assumed from memory — update this table whenever a dependency's pinned version changes.

**RESOLVED — Redis → Valkey migration (see [ADR 0020](docs/adr/0020-redis-to-valkey.md)):** originally, `redis:7-alpine` as pinned in `docker-compose.yml` was checked with `redis-server --version` inside the actual running container during Phase 23's documentation review and resolved to **Redis 7.4.10**, which is under Redis Ltd's post-relicense **RSALv2/SSPLv1** dual license, not the older BSD-3-Clause terms — a real open item flagging that a legal opinion was needed before any redistribution/commercial use of OpenRBI as-is. That review is now moot: `docker-compose.yml`'s `redis` service now runs `valkey/valkey:8-alpine` instead (the service/hostname stays named `redis` — only the image changed, no client code or config key changed), a Redis-protocol-compatible fork under **BSD-3-Clause**. Every Redis primitive this project actually uses (`SET`/`GET`/`DELETE`/`SCAN`/`INCR`/`EXPIRE`/`TTL`/`GETDEL`/`PING`) was individually verified against the real running Valkey container before this switch, including `GETDEL` specifically (`app/core/release_tokens.py`'s single-use download tokens) since it's a newer command some forks lag on — Valkey supports it identically. This paragraph is kept, not deleted, as the record of why Redis was originally chosen and why the project moved off it.
