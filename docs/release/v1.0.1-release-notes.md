# OpenRBI v1.0.1

## Security Hardening

- LDAPS certificate verification is explicitly enforced, with support for a read-only custom CA bundle.
- Required browser-network isolation is surfaced through system health and can be reapplied automatically after host restarts.
- State-changing requests require signed double-submit CSRF protection in addition to the existing SameSite cookie policy.
- Concurrent replay of a single recovery code is prevented with database row locking.
- Downloads have a configurable maximum size before the backend fetches their content into memory.
- The reverse proxy now sends a restrictive Content Security Policy.
- Reading the LDAP configuration creates an audit event.

## Reliability

- Restore now performs a light post-restore check for database readiness, schema accessibility, and quarantine-storage access.
- Existing fresh-install, upgrade, backup/restore, LDAP, fault-injection, and security regression gates remain required for release publication.

## Operational Improvements

- Network-isolation status is visible in aggregate system health.
- A systemd service and timer can reapply and reconfirm the required host firewall policy.
- Dependabot now monitors Python, npm, Docker, and GitHub Actions dependencies.
- Local builds embed the actual version, commit SHA, and build date instead of static or unknown metadata.
- Release tags are protected from deletion and non-fast-forward updates by a repository ruleset.

## Documentation

- Backup documentation explicitly identifies `.env`, the TOTP encryption key, and TLS material as separate operator-managed backup items.
- Stale pre-1.0 project-status language was removed.
- The supported Compact deployment and remaining technology previews remain explicitly distinguished.

## Upgrade Notes

- Back up PostgreSQL and quarantine storage with the documented v1.0.0 procedure before upgrading.
- Preserve and separately protect the existing `.env`, especially `OPENRBI_TOTP_SECRET_ENCRYPTION_KEY`, as well as TLS keys and certificates.
- Apply the documented migrations and reapply/verify network isolation after the upgrade.
- In-place database downgrade is not supported; rollback uses the pre-upgrade backup and the previous release artifacts.
- General availability remains gated on a real-host upgrade from the published v1.0.0 artifacts to the published release candidate.

## Known Limitations

- The supported production topology remains Compact, single-host, rootful Docker on x86_64 Linux.
- Segmented deployment and gVisor remain technology previews.
- OpenRBI does not provide high availability, enterprise identity federation, full DLP/CDR, or protection against a compromised Docker host or malicious infrastructure administrator.

## Deferred to 1.1

- A maintained base-image digest-pinning and rotation policy.
- Broader supported-configuration documentation refinements.
- Administrative step-up-authentication policy review.
- Non-release-blocking repository and contributor-experience improvements.
